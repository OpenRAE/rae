# Requirement reference

Use each `<UID>/requirement.md` file for its exact requirement statement and metadata.
The UID remains the record identity.

The frontmatter gives status.
When present, the traceability section links delivery and checks.
Some draft and deprecated records have no traceability section.
Status alone does not prove that current code works.
Check the linked code and tests at the revision you are studying.

These files are reference, not tutorials or operating instructions.
Keep obligations, conditions, identifiers, and recorded traceability intact.
The [decision index](../decisions/adrs/README.md) explains architectural choices.
The [research entry](../research/index.md) separates those choices from observed evidence.

For delivery scope, use the [issue-bound scope reference](../governance/requirement-scopes/README.md).
A scope manifest assigns files to requirements; it does not change a requirement statement.
For contributor steps, use the [development workflow](../DEVELOPMENT_WORKFLOW.md).
